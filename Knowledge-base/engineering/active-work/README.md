# Active Work Records

This directory contains living records for work that is currently in progress. It is the place to
resume a task after a conversation, context compaction, handoff, or branch change.

## Naming and lifecycle

- Use one file per active phase or workstream: `phase-<number>-<slug>.md`.
- Update the record after meaningful implementation, database, test, merge, or deployment actions.
- Keep exact commands and concise results; never include secret values.
- Mark each item `Observed`, `Verified`, `Assumed`, `Deferred`, or `Blocked`.
- When the work is complete, retain the record as the final handoff and link its dated audit entry.

## Required sections

1. Objective and governing plan.
2. Current repository, branch, worktree, and environment snapshot.
3. Changed surfaces and external state changes.
4. Verification matrix with fresh evidence.
5. Decisions, assumptions, and deferrals.
6. Ordered next actions and handoff notes.

Active records are current-state documents; they do not replace phase plans, policy decisions, or
append-only audits.
