# Phase 18.5 Direct WebRTC + TURN as-built audit

**Date:** 19 September 2026
**Scope:** Synthetic implementation and current linked-database verification; no real-user activation
**Repository:** Orion, branch `codex/phase-18.5-direct-webrtc-turn`

## Outcome

Phase 18.5's authorized implementation slice is implemented and verified against local services and
the existing linked database. It contains a
disabled-by-default server admission boundary, appointment-scoped Direct WebRTC sessions, a
dedicated in-memory signaling gateway, short-lived TURN REST/HMAC credential issuance, an admin
kill switch, a protected responsive meeting route, and explicit desktop/mobile two-party coverage.
No real-user activation, TURN/signaling provisioning, Edge Function deployment, or website deployment
was performed. The three Phase 18.5 database migrations were applied to the linked Supabase project
after explicit user authorization and verified against the remote migration list.

## Implemented boundary

- `video_sessions` and the service-role-only access/control RPCs enforce the booked appointment,
  assigned patient/psychiatrist relationship, 15-minute early-open window, session end, and kill
  switch. Admins and unrelated participants are denied.
- `video-session-access` signs short-lived signaling admission and TURN credentials without storing
  signaling payloads or browser secrets; `video-control` exposes the admin-only toggle boundary.
- The synthetic signaling gateway accepts one patient and one assigned psychiatrist, forwards only
  offer/answer/ICE setup messages, bounds message size, handles heartbeats/leave, and supports real
  SDP-sized WebSocket frames.
- The UI requires an explicit camera/microphone action and uses the Direct WebRTC route only when the
  advisory UI flag is enabled; server admission remains authoritative. The historical JaaS route is
  unchanged and remains the default.
